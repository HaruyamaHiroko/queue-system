# 窓口混雑解消システム 要件定義書

## 1. プロジェクト概要

役所等の窓口における待ち時間の混雑を解消するため、発番・呼び出しシステムのプロトタイプを開発する。学習目的（TypeScript / React / Node.js）を兼ねたウォーターフォール型開発で進める。

## 2. 対象範囲（スコープ）

- 単一窓口（カウンター）を対象とした最小構成のプロトタイプ
- 将来的な複数窓口対応は本フェーズの対象外（拡張性は意識するが実装はしない）

## 3. 利用者・アクター

| アクター | 役割 |
|---|---|
| 利用者 | 受付で番号を受け取り、呼び出しを待つ |
| 窓口担当者（管理者） | 「次の人を呼ぶ」操作を行い、対応する利用者を呼び出す |

## 4. 機能要件

### 4.1 発番機能
- 利用者が受付操作を行うと、連番の番号（整理券番号）が発行される
- 番号は1から始まる連番とする（運用開始時、または日次でリセットする想定。リセット仕様は設計フェーズで確定）
- 同一利用者による重複発券を防ぐため、ブラウザのlocalStorageに有効な整理券番号を保持している間は「番号を取る」操作を非表示にする
  - **既知の制約**: 本方式はブラウザ・端末単位の制御であり、ブラウザ変更・シークレットウィンドウ・localStorage削除・別端末の使用等により回避可能。サーバー側での厳密な重複防止は行わない（プロトタイプとしての割り切り）
- 「番号を取る」ボタン押下時は確認ポップアップを表示し、誤操作による発券を防止する

### 4.2 呼び出し表示機能
- 現在呼び出し中の番号をブラウザ上に表示する
- レスポンシブデザインとし、PC・スマートフォンいずれでも閲覧可能とする
- 待機人数を表示する。表示画面によって算出範囲が異なる
  - 共有ディスプレイ画面: 全体の待機人数（呼出し中番号より後ろ、発券済番号までの未キャンセル件数）
  - 利用者向け画面（発券後）: 自分より前の待ち人数（呼出し中番号より後ろ、自分の番号の1つ前までの未キャンセル件数）

### 4.3 管理者操作機能
- 窓口担当者が「次の人を呼ぶ」ボタンを操作すると、呼び出し中番号が1つ進む
- 現在の呼び出し中番号・発券済番号を管理画面上で確認できる

### 4.4 キャンセル機能
- 利用者が自身の整理券番号をキャンセル（無効化）できる
- キャンセルされた番号は呼び出し対象から除外される
- キャンセル後の待機人数表示は、キャンセル分を差し引いた実態に近い人数とする

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 動作環境 | Webブラウザ(PC・スマートフォン対応)。対応ブラウザはGoogle Chrome、Microsoft Edgeの最新版を想定(Safari、Firefox等は対象外)。動作確認時点(2026年8月17日)のバージョンは以下の通り(いずれも自動更新されるため、今後のバージョンとは異なる可能性がある)<br>・Chrome: バージョン 151.0.7922.138(公式ビルド)(64 ビット)<br>・Edge: バージョン 151.0.4129.86(公式ビルド)(64 ビット) |
| 想定利用規模 | プロトタイプのため小規模（同時アクセス数十件程度を想定） |
| データ永続化 | プロトタイプ段階ではメモリ上またはシンプルなDBで可 |
| リアルタイム性 | 呼び出し番号の更新は数秒程度の遅延を許容（ポーリング可）。自動更新間隔は60秒とする |

## 6. 画面一覧（想定）

全画面共通で、ヘッダーに当該システムを利用する施設名を表示する。

1. **共有ディスプレイ画面** - 待合室設置用。個人情報は含めず、現在の呼出し中番号・発券済番号・待機人数のみを表示。手動更新ボタン＋自動ポーリング(60秒間隔)
2. **利用者向け画面** - 個人のスマートフォン等で閲覧。1画面内で状態遷移する
   - 発券前: 現在の呼出し中番号・待機人数の表示＋「番号を取る」ボタン。手動更新ボタン＋自動ポーリング(60秒間隔)
   - 確認ポップアップ: 「番号を取る」押下時に表示し、誤操作を防止
   - 発券後: 「呼出し中番号」＋「あなたの番号」＋「あなたより前の待ち人数」＋「キャンセルする」ボタン。手動更新ボタン＋自動ポーリング(60秒間隔)
   - 状態判定はブラウザのlocalStorageに基づく(画面遷移ではなく同一画面内の表示切り替え)
3. **管理者操作画面** - 「次の人を呼ぶ」ボタン、現在の状況確認

## 7. 今後の検討事項（設計フェーズで確定）

- 番号のリセットタイミング（日次リセットの方式）
- 発券済番号と呼出し中番号のデータ管理方式（サーバー側での保持方法）
- 画面更新方式（ポーリング／WebSocket等）
- 複数の利用者が同時に発券した場合の番号重複防止（排他制御）
- キャンセルした番号を呼出し中番号が「通過」する際の扱い（スキップ処理の方式）
- 利用者が自分の番号をキャンセルする際の本人確認方法（番号を知っていれば誰でもキャンセル可能とするか等）

## 8. 使用技術・インフラ構成

- フロントエンド: React + TypeScript(AWS外の無料ホスティング、例:GitHub Pages等で配信)
- バックエンドAPI: Node.js(TypeScript) on AWS Lambda(**Lambda Function URLs**を使用し、API Gatewayは使用しない)
- データストア: Amazon DynamoDB

### 8.1 コスト方針
- AWSアカウント作成から12ヶ月以上経過しており、12ヶ月無料枠(API Gateway、S3、EC2、RDS等)は対象外
- **Always Free枠(永続無料)に含まれるサービスのみを使用する**
  - Lambda:月100万リクエスト + 40万GB秒
  - DynamoDB:25GBストレージ + 25 RCU/WCU
- API Gatewayの代わりにLambda Function URLsでHTTPSエンドポイントを直接公開する
- フロントエンドはS3/CloudFrontを使わず、AWS外の無料ホスティングサービスを利用する
