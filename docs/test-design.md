# テスト設計書

## 1. テストの目的・方針

要件定義書・API設計書・データ設計書・詳細設計書で定めた仕様通りにシステムが動作することを確認する。プロトタイプ(学習目的)であることを踏まえ、正常系を中心に、業務上重要な異常系(認証エラー・不正操作の防止)も含めて確認する。

## 2. テストレベル

| レベル | 内容 | 実施状況 |
|---|---|---|
| 結合テスト | 実際にデプロイした環境(AWS Lambda + DynamoDB + GitHub Pages)で、画面操作を通じてAPIとDBまで含めた一連の動作を確認する | 一部実施済み(4章参照) |
| 受け入れテスト | 実運用を想定した最終確認 | 未実施 |

単体テスト(関数単位の自動テストコード)は、本プロトタイプでは範囲外とする。

## 4. 結合テストの実施結果(2026年8月20日実施)

以下の一連の操作フローを実施し、すべて期待通りの結果を確認した(T-01, T-02, T-05, T-10, T-14, T-15, T-16に対応)。

1. 3画面(共有ディスプレイ・利用者向け・管理者)を開き、初期状態(000/0)を確認
2. 1人目が発券 → 番号001が表示される
3. 共有ディスプレイを更新 → 発券済001・待機人数1を確認
4. 2人目が別ブラウザで発券 → 番号002
5. 2人目(002番)をキャンセル → 発券前の画面に戻ることを確認
6. 2人目が再発券 → 番号003
7. 管理者画面で「次の人を呼ぶ」 → キャンセル済みの002がスキップされ、003が呼び出されることを確認
8. 1人目の画面で呼出し中番号の更新を確認
9. 呼び出せる番号がない状態で再度「次の人を呼ぶ」 → 「呼び出せる番号がありません」の表示を確認
